# CS2 Optimization: 自動適用型の描画軽量化MOD 設計

## 目的と前提

Cities: Skylines II に導入するだけで、都市の描画負荷を控えめに減らす個人用コードMODを作る。ユーザーの RX 7800 XT 16 GB / Ryzen 7 9700X と既存の Write Everywhere を想定する。成功の判定は同じ都市・視点・条件でのフレーム時間、1% low、見た目の比較による。改善幅は未確認であり、FPSの保証値は置かない。

実装先は空の非公開リポジトリ `pengin0503/CS2-Optimization` とする。既存の CS2 Runtime Asset Auditor には組み込まない。ゲームのシミュレーション、セーブデータ、`Settings.coc` は変更しない。起動前半やロード時間の改善はこのMODの目的に含めない。

## 検討した方式と採用案

| 方式 | 評価 |
|---|---|
| CS2PerformancePatcher の設定ツールをそのまま配布 | 幅広い画質設定を扱えるが、ゲーム外での実行と `Settings.coc` の編集が必要。導入だけで有効という要件に合わない。 |
| CS2PerformancePatcher の `Cs2Saver` を丸ごと統合 | 実証済みの仕組みを利用できるが、色調・材質変更、CSV出力、強いプリセットまで持ち込み、機能や衝突面が増える。 |
| **`Cs2Saver` の描画距離と影の制御だけを移植・整理** | **採用。** Prefab単位のLOD下限とHDRPの影距離を独立した機能として構成する。 |
| Write Everywhere のコードをコピー・外部Harmonyで上書き | 同MODのECSコンポーネント、ジョブ、レンダラーと密結合。同期を外しただけでは依存関係が壊れる。初版に含めない。 |

調査の基準点は `NspxMiguel/CS2PerformancePatcher` の commit `69015dd90cfc667c100beb16fd158a43a9e03a23`、`klyte45/CS2-WriteEverywhere` の commit `ac76064f67860d3421a565a25fff1917e15710c2`。前者は GPL-3.0 なので、移植した部分の著作権表示・ライセンスを維持する。後者は実装の調査にだけ用い、コードは複製しない。ゲームDLLを成果物に含めない。

## 動作

設定 `Mode` は `Auto`（新規導入時の既定値）、`Off`、`Custom`。既存ユーザーの保存済み設定を毎起動上書きしない。

| 状況 | 影距離 | 小物PrefabのLOD下限 | 木・市民・車両・建物 |
|---|---:|---:|---|
| `Auto`、Write Everywhereなし | 300 m | 元値 +6（およそ描画距離半分） | 変更しない |
| `Auto`、Write Everywhereあり | 300 m | 変更しない | 変更しない |
| `Off` | 変更しない | 変更しない | 変更しない |
| `Custom` | 無変更 / 100 / 175 / 300 / 500 m | 無変更 / +6 / +12 を選択 | 変更しない |

影は既にゲーム設定で有効なときだけ到達距離を制限する。MODから太陽光やシャドウマップ解像度、カスケード数を強制変更しない。ゲーム設定で影が無効なら影機能は無効と表示する。Write Everywhere があるとき小物を既定で除外するのは、看板や文字の早期消失を避けるためであり、手動の `Custom` では変更できる。`Custom` に切り替えると現在の実効値をコピーしてから個別に変更する。

`Cs2Saver` が同時に導入されている場合は描画処理全体を停止し、設定画面とログで理由を伝える。その他の描画MODは網羅的に判定できないため、利用者が個別にオフへ戻せるようにする。対応対象は最初にゲーム版 `1.6.0f1` と対応するUnity/HDRPの参照で検証する。未検証のゲーム版では描画処理を停止し、警告を記録する。バージョン判定は実行時に取得したゲーム版を基準とし、型・フィールドの適合性も確認する。

## 構成とデータの流れ

`CS2Optimization.Mod` が設定を読み込んで有効プロファイルを決定し、二つの独立した制御器へ渡す。

設定方針と元値管理はゲーム参照を持たない `CS2Optimization.Core` に置く。ゲーム用アセンブリはこのCoreを参照する。純粋ロジックのテストはゲームDLLなしで実行できる。

- `PrefabLodController` は `ObjectInitializeSystem` の後に、小物Prefabの `ObjectGeometryData.m_MinLod` を変更する。対象は `StaticObjectData` / `NetObjectData` を持ち、`BuildingData`、樹木、植物を持たないPrefab。Prefabごとの元値を都市単位で保持し、同じ設定の再適用でも値を積み重ねない。新しいPrefabを検出したときと設定変更時だけ書き込む。
- `ShadowDistanceController` は影を使う都市でHDRPの `HDShadowSettings.maxShadowDistance` だけを上書きする。自分が作成したVolumeだけを所有し、オフ・破棄時に無効化して破棄する。ゲーム側のVolumeや設定ファイルは書き換えない。
- `EffectiveProfilePolicy` は保存済み設定、WE検出、`Cs2Saver`との重複、ゲーム版の可否から実効値と停止理由を決める。設定画面には要求値と実際に適用された値を示す。

検出するWEアセンブリ名は `BelzontWE`、競合するCs2Saverは `Cs2Saver`。初回登録時と都市ロード時に再評価する。影の有効状態はゲームの設定変更を拾えるよう低頻度で再確認し、無効になれば自前Volumeの影overrideを止める。無効値の保存設定は安全側へ倒し、描画変更せず設定UIに理由を出す。

都市を離れるときは現在の都市のPrefab値を復元し、保持した元値を破棄する。次の都市では新しい基準値を取得する。実行中の無効化、MODの破棄でも同期的に復元する。復元できないEntityは書き込まず記録し、次回のゲーム起動時には元のゲーム値から始められるよう、変更値を保存しない。

## エラーと負荷

個別機能の初期化に失敗したら、その機能だけ停止して一度ログを出す。毎フレーム同じ警告を出さない。適用中の失敗は取得済みの元値を使って復元を試みる。ネイティブ配列、Job依存、Volumeを確実に解放する。毎フレーム全市民・全車両を走査しない。通常の更新は小さな状態確認に留め、Prefabへの変更はロード・新規追加・設定変更時のみ行う。

## 検証と完了条件

1. 純粋な方針関数とLOD計算を自動テストする。初回設定、既存設定、WEあり、重複MOD、未対応ゲーム版、`Off`、`Custom`、連続適用、都市切替、最大値255、復元を含む。
2. ゲームDLLにリンクしてビルドする。添付の参照ZIPにはHDRP用の `Unity.RenderPipelines.HighDefinition.Runtime.dll` と `Unity.RenderPipelines.Core.Runtime.dll` がないため、影機能を含むビルドにはユーザーのゲームインストールからこれらを参照する。配布ZIPへは同梱しない。
3. ゲーム内で同じセーブ・視点・時間帯、速度1、60秒以上の計測を各条件3回行う。ベースライン、`Auto`、`Off`、影のみ、小物のみの順序を入れ替え、ウォームアップを除く。平均FPSだけでなくCPU/GPUフレーム時間と1% lowを記録し、同条件のスクリーンショットで看板・文字・樹木・近景の見た目を確認する。AuditorのDeep Captureや巨大JSON出力は計測区間に重ねない。
4. 新しい都市への切替、設定変更、MOD無効化、WE併用、影オフ、未対応版、`Cs2Saver`併用をゲーム内で確認する。起動不能・描画欠落・復元失敗があれば公開可能なビルドとして扱わない。実測で改善が確認できない既定調整は外す。

この設計は初版の対象を描画負荷に限定する。WE固有の4.36 msの内訳やJob完了待ちを改善する作業は、別途WE本体の版と再測定結果に基づいて判断する。
